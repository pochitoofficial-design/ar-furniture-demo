# 最初のリリース（MVP）の範囲

「完璧を目指さず、まず出してフィードバックで直す」ための最小構成。サーバーなし、静的ファイルだけで提供できる形にする。

## 提供するもの
1. **埋め込みタグ `embed.js`** — 商品ページに 1 行貼ると「自分の部屋に置いてみる」ボタンと 3D ビューが付く。iOS / Android の AR に対応。色バリエーションと寸法も表示。
2. **カタログ `catalog.json`** — SKU ごとの 3D モデルの所在と寸法。これを差し替えれば商品が増える。
3. **モデル準備ツール `tools/prepare.html`** — 外注や AI 生成で得た GLB を読み込み、実寸に合わせて書き出す。カタログ用の JSON も出す。
4. **生成パイプライン `pipeline/generate.py`** — 商品写真から Meshy の API で GLB と USDZ を作る（API キーが必要。実行は制作担当の手元）。
5. **計測** — ボタン表示・AR 開始・失敗を `dataLayer` と `gtag` に送る。顧客の GA4 でそのまま集計できる。

## 今回やらないこと（フィードバック後）
- 管理画面（登録・承認・タグ発行の Web UI）。当面はカタログ JSON を手で編集する。
- 自社サーバーでの配信・認証・利用量計測。当面は GitHub Pages か顧客サイトに同梱。
- ARボタンあり／なしの A/B 振り分け。当面は GA4 のイベントで AR 利用者と非利用者の購入率を比べる。
- 搬入経路チェック、複数配置、物件モードの製品化。

## 提供の流れ
1. 顧客から商品写真と寸法（幅・奥行・高さ）を受け取る
2. `pipeline/generate.py` で GLB / USDZ を生成（または外注）
3. `tools/prepare.html` で実寸に合わせて書き出し、`catalog.json` に追記
4. モデルとカタログを配信先に置き、顧客の商品ページに `embed.js` のタグを貼る
5. GA4 のイベントで AR 起動率と購入率の差を毎週見る
